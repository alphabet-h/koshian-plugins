# koshian-plugins Feature Ideas

これから検討したい改善候補の **vault**。効果・難易度・制約整合で優先度を判断し、
着手したものは末尾の台帳へ移す。**このファイルは実装計画を持たない**（→ 棲み分け表）。

**プロジェクト不変条件**: 各プラグインは自己完結する（LICENSE / CHANGELOG / README を個別に持ち、
インストール後は自分のディレクトリの外を参照しない）。ルート `documents/` は廃止済みで、
社外に出さないメモは `.dev/`（git 追跡外）に置く。ドキュメントは日本語を正本とする。
これらを壊す候補は 制約 `⚠️` / `❌` として扱う。

## 既存 doc との棲み分け

| パス | 役割 | vault との関係 |
|---|---|---|
| `docs/feature-ideas.md` (本ファイル) | アイデアの index + 台帳 2 表 | — |
| `docs/feature-ideas/FI-NNN*.md` | 個別アイデアの**詳細ファイル** | 備考からリンク |
| `docs/superpowers/specs/` | 設計仕様書 | vault ディレクトリに置かない |
| `docs/superpowers/plans/` | 実装計画（`superpowers:writing-plans` の出力） | 同上 |
| `plugins/*/CHANGELOG.md` | 各プラグインのリリース履歴 | 実装済み台帳と二重管理しない |
| `.dev/` (git 追跡外) | 社外に出さない作業メモ | vault には持ち込まない |

## 凡例

| 列 | 値 | 意味 |
|---|---|---|
| ID | `FI-001` | カテゴリ非依存の通し番号。**一度振ったら変えない** |
| 状態 | `idea` | 起票済み・未着手（既定値） |
| 状態 | `probing` | 深掘り中。詳細ファイルあり、採否は未決 |
| 状態 | `planned` | spec / plan を書いた。実装フローへ引き継ぎ済み |
| 状態 | `frozen` | 発火条件待ち。期限を持たない |
| 効果 | 大 / 中 / 小 | 大 = 中核指標が数値で動く / 中 = 痛点が減る / 小 = あると便利 |
| 難易度 | 低 / 中 / 高 / 極高 | 低 = 半日〜1 日 / 中 = 数日 / 高 = 1〜2 週 / 極高 = 月単位 |
| 制約 | ✅ / ⚠️ / ❌ | 不変条件を壊さないか。`⚠️` は**昇格条件を備考に必ず書く** |

**表記の規律**: 状態は 4 語を装飾なしで書く。`done` / `declined` は index に残さず行ごと台帳へ移す。
備考は 200 字以内で、超えたら詳細ファイルへ昇格する。日付つきの追記は詳細ファイルの `## 判定履歴` へ書く。

## 優先度ピック (2026-08-16 版)

動機は **自分の使い勝手**。配布や発見性より、日々使う道具としての完成度を優先する。

**「次に手を付けるなら」個人的ベット順**

1. **FI-022 (trap-book v0.1.1)** — 今日見つかった実害。作業は version バンプと CHANGELOG だけで、放置すると「直したのに直っていない」状態が続く
2. **FI-025 (feature-ideation v0.2 hook)** — 「vault は増えるが見直されない」を実際に潰せるのはこれだけ。使い勝手に直結する
3. **FI-002 + FI-001 + FI-006 (CI 三点セット)** — バンドルで 1 日。やり忘れを人力で見つける状態そのものを機械化する
4. **FI-027 (横断 doctor)** — 「入っているのに読み込まれていない」を自分で検出できるようにする。FI-002 の実行時版
5. **FI-029 (CLAUDE_EFFORT の修正)** — 軽い。今日のバグをその日のうちに閉じる
6. **FI-026 (trap-book KB → harvest)** — 自分で思いつかない方向のアイデアを機械に拾わせる。差別化としても効く
7. **FI-024 (design-kit / design-forge のドッグフーディング)** — 使っていないものは腐る。trap-book のスキル未ロードが 4 ヶ月見つからなかったのと同じ構図

**意識的に後回し**

- **FI-017 / FI-020 (掲載申請・英語併記)** — 動機が「自分の使い勝手」である以上、読者を増やす投資は後回しでよい
- **FI-012 / FI-013 (共通基盤)** — `../` 制約を symlink で回避する設計コストが、重複を消す利得を上回る
- **FI-011 (commands → skills 移行)** — legacy 扱いでも動く。壊す理由がない

**改訂トリガ**（いずれか成立したら選び直す。`check` が検出して提案する）

- **T1** 前回ピックから **90 日**経過
- **T2** ピック項目の**過半数**が done / declined になった
- **T3** 前回ピック以降に **10 件以上**の新規アイデアを追加した
- **T4** **ピックに載っていない ID が実装済み台帳に入った**

## 実装済み台帳

実装・出荷済みの候補。詳細な経緯は参照先が正本。

| ID | 名前 | 完了日 | 証跡 | 知見 |
|---|---|---|---|---|

- **`証跡` は空欄禁止**。PR 番号 / タグ・version / commit / ADR のいずれかを最低 1 つ
- **`知見` は空欄禁止**。特に**起票時の想定が外れた点**を残す
- 新しい行は**先頭に追記**（完了日の降順）

## 更新ルール

1. 新しいアイデアは**ペンディング**欄に自由記述で追記してよい。ID 付与は後でよい
2. 「やるかもしれない」段階で ID を振ってカテゴリ表へ（状態 `idea`）。
   **次の ID = max(index + 台帳 2 表) + 1**。欠番は再利用しない
3. 備考が 200 字を超える / 論点・URL・コード断片が要る → `docs/feature-ideas/FI-NNN.md` へ昇格し、状態を `probing` に。
   **評価が動いたときの日付つき追記は詳細ファイルの `## 判定履歴` へ**
4. `docs/feature-ideas/` 直下のファイル名は **`FI-` か `archive-` で始まる**こと。
   実装計画は `docs/superpowers/plans/`、設計仕様は `docs/superpowers/specs/` へ置く
5. **孤児を作らない** — `docs/feature-ideas/` の全ファイルは index か詳細ファイルから最低 1 本リンクされること
6. 再評価の時期を**自分で決められる**なら再評価キューへ日付で書く。
   **外部条件待ちなら状態 `frozen`** にして備考に発火条件を書く（`frozen` が 5 件を超えたら別ファイルへ切り出す）
7. 実装・出荷したら**行ごと実装済み台帳へ**、見送ったら**行ごと不採用の記録へ**移す
8. カテゴリを棚卸したらそのカテゴリの `最終確認` を更新。**全行を突合したときだけ** frontmatter の `last_sweep` を更新する
9. 外部プラットフォーム前提（Claude Code の仕様等）を条件にした行は、棚卸のたびに公式 docs を引き直す
10. vault を更新したら末尾の**変更履歴**に 1 行追記する
