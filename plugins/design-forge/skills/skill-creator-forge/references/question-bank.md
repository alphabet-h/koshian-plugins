# Question Bank

forge の Step 3（動的質問生成）で使うカテゴリ別質問パターン集。**業種を問わず**使える設計で、各質問のプレースホルダには IT と非 IT の両方の例示を並べている。各カテゴリから 3-7 件を選んで AskUserQuestion で提示する。

## 選抜ルール

- **必須 3 件**: 各カテゴリの先頭 3 件は生成後の SKILL.md 品質に直結するので必ず採用
- **任意 0-4 件**: ペルソナの具体性に応じて追加選抜（「なんとなく作って」系は任意を減らす、「こういう細かい要求」系は任意を増やす）
- **統合質問**: 同じ回答がほぼ確定する 2 問は統合して 1 問に（冗長回避）
- **既出回答の省略**: ペルソナ文（Step 1）で既に答えられている項目は選抜から外す（例: ユーザが既に「Tailwind で」と言っていれば、「対象技術スタック」の質問は出さない）

## カテゴリ別質問パターン

以下の質問文はそのまま AskUserQuestion に流し込んで OK。`placeholder` は業種別に複数例示し、ユーザが自ドメインに引き寄せて回答しやすくしている。

### Generator（必須 3 件 + 任意 4 件）

**必須**:

1. **トリガフレーズ** (text, required)
   - prompt: "ユーザがどう発話したらこのスキルが起動すべきか（2-3 例、コンマ区切り）"
   - placeholder: "ボタン作って / 契約書ドラフトお願い / 授業計画立てて / 申請書下書いて"

2. **入力の典型例** (text, required)
   - prompt: "ユーザ入力の典型例を 2-3 件、コンマ区切りで"
   - placeholder: "黒背景の警告ボタン / NDA 契約書 (6 ヶ月) / 小学校 3 年算数の 45 分授業 / 建築確認申請 木造 2 階建"

3. **出力フォーマット** (choice, required)
   - prompt: "生成物の形式"
   - choices: [プレーンテキスト, Markdown, PDF 出力向け Markdown, docx 想定構造, HTML, SVG, PNG, JSON, Tailwind JSX/TSX, Vue SFC, 自由入力]
   - 注: 業種を問わない一般フォーマット（プレーンテキスト / Markdown / PDF / docx）を前方に置き、Web/IT 特化フォーマット（HTML / SVG / Tailwind 等）は後方。用途によって並びを入れ替えても OK。

**任意**:

4. **参考資料（reference）** (text, optional)
   - prompt: "references/ に置きたい URL / 画像 / 既存ガイドライン等（コンマ区切り、後で WebFetch する）"
   - placeholder: "https://docs.example.com/style-guide / 過去の優良な契約書 PDF / 学習指導要領"

5. **並列サブエージェント** (choice, optional)
   - prompt: "生成時に 3-5 案を並列で作って比較する？"
   - choices: ["並列 3-5 案 → ベスト選択", "1 案だけ直球", "質問フェーズで毎回聞く"]

6. **失敗パターン（やらないこと）** (text, optional)
   - prompt: "デフォルトで起こしがちなミス（3-5 例）"
   - placeholder: "Inter + 紫グラデに収束 / 業界用語を避けすぎて曖昧になる / 一般論に終始して具体性を欠く"

7. **ドメイン固定値** (text, optional)
   - prompt: "ブランド / 会社 / 組織固有の固定値（色 / フォント / 定型文 / ロゴ 等、任意）"
   - placeholder: "#1a2b3c / Playfair Display / 『株式会社〇〇』という表記 / 決まった免責文言"

### Auditor（必須 3 件 + 任意 4 件）

**必須**:

1. **監査対象** (choice, required)
   - prompt: "何を評価する？"
   - choices: [Web UI コード, CSS/JS アニメーション, アクセシビリティ, ブランド一貫性, 文書の法令/規約遵守, 引用/参考文献の正確性, 図面/設計書の仕様適合, 自由入力]

2. **採点方式** (choice, required)
   - prompt: "スコア形式"
   - choices: ["0-100 score", "pass-fail", "重大度ラベル (critical/warning/info)", "5 段階評価 (◎○△×✗)", "S-F tier (Web アニメーション監査等、Motion AI Kit 風)"]
   - 注: 前 4 択は業種非依存。S-F tier は元来 Web アニメーション監査由来で、非 IT では直感的でない可能性があるので末尾に配置。

3. **ルール集ソース** (text, required)
   - prompt: "監査ルールの出処（URL / 既存ガイドライン / 自作）"
   - placeholder: "WCAG 2.2 / 自社ブランドガイド / Vercel Web Design Guidelines / 建築基準法 / ブルーブック引用ルール / 学習指導要領"

**任意**:

4. **違反時の修正案有無** (choice, optional)
   - prompt: "違反ごとに修正案を出す？"
   - choices: ["必ず修正案を添える", "重大な違反のみ修正案", "修正案なし（指摘だけ）"]

5. **レポート形式** (choice, optional)
   - prompt: "監査結果の出力"
   - choices: [Markdown 表, JSON, 人間向け散文, コメントを対象ファイルに直接追記, 業界指定フォーマット（自由入力）]

6. **サンプリング方針** (text, optional)
   - prompt: "対象が多い場合の抜粋方式（例: ランダム 10 件 / 上位重要度順 / 全件）"

7. **False positive 対策** (text, optional)
   - prompt: "ルールに当てはまるが意図的な場合の例外表記（コメント注釈 / 特記事項 / 備考欄 など）"

### Process（必須 3 件 + 任意 4 件）

**必須**:

1. **ステップ列** (text, required)
   - prompt: "実行する手順を 3-7 ステップで列挙（番号付きで）"
   - placeholder: "1. export → 2. optimize → 3. upload / 1. 見積もり作成 → 2. 社内承認 → 3. 顧客送付 / 1. 教材準備 → 2. 配布 → 3. 採点 → 4. 返却"

2. **各ステップの I/O** (text, required)
   - prompt: "ステップ間でやり取りするデータの形式（Markdown / JSON / ファイルパス / 紙書類 / 口頭確認 等）"

3. **副作用の存在** (choice, required)
   - prompt: "外部に影響する操作（git push / 通知送信 / メール送付 / 提出書類作成 / 課金対象 API 呼び出し）はあるか？"
   - choices: ["無い（完全ドライラン）", "ある - 各副作用の前に必ず AskUserQuestion で確認する", "ある - 最初に一括承認したら以降は自動"]

**任意**:

4. **中断時のリカバリ** (text, optional)
   - prompt: "途中で失敗した場合の再実行方法（冪等 / 続きから / 最初から / 巻き戻し）"

5. **並列化可能なステップ** (text, optional)
   - prompt: "独立して並列化できるステップはあるか（Task tool で subagent 並列候補）"

6. **進捗表示** (choice, optional)
   - prompt: "長時間ステップの進捗をどう見せる？"
   - choices: ["% 表示", "ステップ番号だけ", "口頭レポート", "何も出さない（完了時のみ）"]

7. **ログ / 監査証跡** (text, optional)
   - prompt: "実行ログをどこに残す？（不要なら省略）"
   - placeholder: "./logs/YYYY-MM-DD.md / 専用 issue にコメント追記 / ファイル名を変えたバックアップ"

### Hybrid（必須 3 件 + 任意 4 件）

**必須**:

1. **構成サブスキル** (text, required)
   - prompt: "組み合わせる動作を列挙（例: 'UI 生成 + アクセシビリティ監査 + レポート'）"
   - placeholder: "契約書ドラフト + 条項レビュー + 修正提案 / 授業計画作成 + 著作権チェック + 保存"

2. **実行順序 / 依存** (choice, required)
   - prompt: "サブ動作は順次か並列か？"
   - choices: ["完全順次（1→2→3）", "1 → (2 並列 3)", "全並列", "条件分岐あり"]

3. **最終出力** (text, required)
   - prompt: "最終的にユーザに返すもの（各サブ出力の束 / 統合レポート / 最終成果物 + 診断）"

**任意**: Generator / Auditor / Process からペルソナに近い質問を 1-3 件流用可（重複削除後）。

## 業種別の補足例（インスピレーション）

全業種対応するための参考資料。generated skill 側で具体化するときに引き出せるよう、典型ドメインの質問補強パターンを書き留めておく。

### Web / ソフトウェア (Generator)

- 対応ブラウザ範囲（Chrome のみ / Safari も / IE11 サポート必要？）
- アクセシビリティ水準（WCAG A / AA / AAA）
- ランタイム制約（Node / Edge / Bun、サーバレス関数のサイズ）

### 建築事務所 (Generator / Process)

- 対象構造（木造 / RC / S 造）
- 対象自治体（役所ごとの様式差異、共通フォーマット or 個別対応）
- 法改正追随（前回申請からの差分検出）

### 法律事務所 (Auditor / Generator)

- 引用フォーマット規則（法務省スタイル / ブルーブック / 裁判所独自）
- 判例ステータス（最高裁で覆された判例の扱い）
- 事件番号正規化（事件番号 / 判例タイムズ番号 / 裁判所 web URL）

### 教育機関 (Generator / Process)

- 学年 / 教科 / 教科書ごとのレベル調整
- 著作権配慮（引用範囲、クレジット表記、コピー可否）
- 授業時間単位（45 分 / 50 分 / 90 分）へのコマ割り

### 経理 / 事務 (Process)

- 法定保存期間（帳票ごとの保管年数）
- 承認フロー（稟議 → 上長承認 → 経理処理）
- 税区分（消費税 10% / 軽減 8% / 非課税 / 不課税）

### 医療 / 介護 (Auditor / Generator)

- 個人情報の匿名化（HIPAA / 個人情報保護法）
- 用語規格（SNOMED CT / ICD-10）
- 記録フォーマット（SOAP / カルテ記録規則）

## 選抜アルゴリズム（SKILL.md 内で参照）

1. ペルソナ（Step 2）からカテゴリ確定
2. 該当カテゴリの **必須 3 件** を先頭に配置
3. Step 1 のフリー入力に応じて任意 0-4 件を選抜（具体性が高い入力 → 任意多め）
4. 同一トピックの重複を削除（例: ペルソナで既にブランド色を言及していれば「ドメイン固定値」質問は省く）
5. ユーザのドメインが上の「業種別の補足例」に当てはまるなら、そこから 1-2 件を**追加で**選抜候補として上位に
6. 残った 3-7 件を AskUserQuestion で 1 件ずつ提示

## A/B 比較観点での配慮

本スキルはテンプレ駆動型のスキル作成スキルと**並列配布された時の比較素材**として機能するよう設計されている。同じタスクを複数アプローチで試すユーザのために:

- **Generator の必須質問**（トリガフレーズ / 入力の典型例 / 出力フォーマット）は、UI コンポーネント系テンプレが聞きそうな項目と似た wording にしてある。比較しやすさ優先。
- **Auditor の必須質問**（監査対象 / 採点方式 / ルール集ソース）も、audit 系テンプレが聞きそうな項目と wording を揃えている。
- 本スキルの差別化ポイント: テンプレが **enum-choice 主体 + 分野固定**なのに対し、本スキルは **フリーテキスト歓迎 + 業種マルチ想定**。違いは質問項目ではなく「入力の自由度」と「業種カバレッジ」にある。
