# Persona Categories

forge の Step 2（ペルソナ分類）で使う 4 カテゴリの定義と判定ヒント。Step 1 のフリー入力を LLM 側で分類し、AskUserQuestion でユーザに最終確認する。

**業種を問わず**使えるよう、各カテゴリに IT と非 IT の両方の具体例を載せている。分類ロジック自体は業種非依存。

## 4 カテゴリ

### Generator

ユーザ入力から**新しい成果物を生成**するスキル。

- **判定ヒント**: 発話中に「作って」「生成して」「書いて」「デザインして」「下書きして」「スケッチして」等の **produce 動詞**
- **例 (IT)**: UI コンポーネント生成 / メール文面生成 / SVG アイコン生成 / スライド作成 / テストコード生成
- **例 (非 IT)**: 建築の確認申請書生成 / 契約書ドラフト / 授業計画案 / レストランのメニュー表 / 広告コピー案
- **生成される SKILL.md の特徴**: 「入力 → 出力フォーマット」を明記、失敗パターンが具体的、reference に良い例 / 悪い例を置く

### Auditor

既存成果物を**評価 / 採点 / 診断**するスキル。

- **判定ヒント**: 「評価して」「監査して」「チェックして」「採点して」「レビューして」「査読して」「添削して」
- **例 (IT)**: アクセシビリティ監査 / ブランド整合性チェック / パフォーマンス診断 / セキュリティレビュー / コード品質レビュー
- **例 (非 IT)**: 法令遵守レビュー / 引用フォーマットチェック / 建築図面の法規適合チェック / 教材の著作権チェック / 営業提案書の構成採点
- **生成される SKILL.md の特徴**: ルール集 / 採点方式 / レポート形式を明記、violation ごとの修正案を必須

### Process

定型作業の**手順を自動化**するスキル。

- **判定ヒント**: 「N ステップで」「手順通り」「いつもの流れで」「ルーティン」「フロー通り」
- **例 (IT)**: リリースノート作成 → push → 通知 / デザインファイル export → 最適化 → アップロード / CI 実行 → 結果通知 → issue 作成
- **例 (非 IT)**: 月次請求書発行 → 送付 → 入金確認 / 入所手続 → 書類準備 → 役所届出 → 完了報告 / 学期末成績処理 → 保護者通知 → 記録保管
- **生成される SKILL.md の特徴**: ステップが番号付きで明記、各ステップの入出力、中断時のリカバリ

### Hybrid

上記を**複数組み合わせた**スキル。

- **判定ヒント**: 「生成して、しかも採点して」「作って手順どおり公開」「診断してから修正案」等、動詞が複数
- **例 (IT)**: コンポーネント生成 + アクセシビリティ監査 + レポート / ブランド資料生成 + 媒体別 export
- **例 (非 IT)**: 契約書ドラフト生成 + 条項レビュー + 修正提案 / 建築図面生成 + 法規チェック + 申請書類セット化
- **生成される SKILL.md の特徴**: サブスキルに相当するセクションを分離、並列可能な部分は Task tool での subagent 並列を示唆

## AskUserQuestion で提示する形

```
Question: 入力内容から「{推測されたカテゴリ}」と判定しました。これで進めますか？
Options:
  - {推測されたカテゴリ} で進める (Recommended)
  - 別カテゴリを選ぶ (Generator / Auditor / Process / Hybrid から)
  - ペルソナ抽出をやり直す (Step 1 に戻る)
```

## エスケープバルブ

1 ターンで判定に自信が持てない場合は、ユーザに「もう少し詳しく: 主な動詞は何？」と追加で 1 問だけ聞く。それでも曖昧なら Hybrid にフォールバック。

## 業種中立性の注意

ペルソナ文に業種特有の用語（「案件」「申請書」「授業」「コード」等）が出てきても、判定は**動詞 / 目的のパターン**で行う。例えば「毎月の請求書を月初に発行して、PDF 化してお客様にメールで送る」は業種は経理 / 法律事務所 / フリーランス等いろいろありうるが、Process として処理すればよい。

generated skill の本文では業種用語をそのまま引き継ぐ（ユーザのドメイン文脈を尊重）。
