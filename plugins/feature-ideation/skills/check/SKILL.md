# vault の状態確認

**このスキルはファイルを一切書き換えない。** 事実を報告し、選択肢を出すところまでが仕事。

## 集計結果（機械生成）

以下は `lib/vault-digest.sh` の実行結果。モデルが生成したものではない。

````
!`bash "${CLAUDE_PLUGIN_ROOT}/lib/vault-digest.sh" $ARGUMENTS || true`
````

## 鉄則

1. **数えない。** 件数は `-- COUNTS --` からそのまま転記する。digest に無い数字を書いてはいけない
2. **日付を計算しない。** 経過日数は digest の値をそのまま使う。「最近」「しばらく前」で置き換えない
3. **勝手に直さない。** 放置や矛盾を見つけても報告するだけ。archive するか、リンクを張るかはユーザが決める
4. **digest に無い ID を作らない**

## digest の読み方

| 行 | 意味と対応 |
|---|---|
| `digest_status: no-vault` | vault が無い。件数の話はせず「引数なしで `/feature-ideation` を起動してアイデア出しから始めましょう」と案内して終了する |
| `digest_status: degraded` | 今日の日付が取れていない。日付系のアラートは信用せず、件数だけ報告してその旨を明記する |
| `vault_candidates:` | vault が複数見つかった。どれを見たかを明示し、違うならパス指定での再実行を促す |
| `overdue` | 再評価キューの期日超過。**機械が断定している。そのまま出す** |
| `LOOSE_OVERDUE` | 本文に書かれた絶対日付の期限。キューに載せ替えることを提案してよい |
| `due_soon` | 7 日以内に期日が来る |
| `stale_sweep` / `stale_category` / `STALE_PROBING` | 全体 / カテゴリ / 個別アイテムの長期未確認 |
| `frozen` | 発火条件待ち。**期限切れではない。混ぜて報告しない** |
| `ledger_incomplete` | 台帳の `証跡` か `知見` が空。実装から vault へ戻る導線が切れている |
| `FOREIGN` | vault ディレクトリの命名規約に反するファイル。`plan` / `spec` / `unknown` の分類つき |
| `ORPHAN` | index からも他の詳細ファイルからも参照されていない |
| `MISSING_DETAIL` | index がリンクしているのに実在しない |
| `XREF` | index の ID が ADR / plan / CHANGELOG から言及されている。**下記の突合に進む** |
| `DANGLING` | 外部が言及している ID が index に無い。起票漏れの可能性 |
| `PICK_TRIGGER` | 優先度ピックの改訂条件が成立した |
| `PARSE WARNINGS` | 表記の規律違反。**件数がずれている可能性があるので必ず伝える** |

## モデルの仕事（ここだけは判断が要る）

### 1. `XREF` の突合 — index は実態に追いついているか

digest は「index の行」と「外部 doc の言及」を並べるだけで、どちらが正しいかは判定していない。
日付が同じでも内容が矛盾していることがある。

`XREF` 行ごとに、外部 doc の該当箇所を Read し、index の行と突き合わせる。食い違っていたら
**何がどう違うかを具体的に書く**。「status が古い」で終わらせない
（例:「index は『候補 2〜4 は未判定』だが、ADR-0011 は 2026-07-25 に候補 3 を Accepted にしている」）。
修正の提案はしてよいが実行はしない。

### 2. `FOREIGN` / `ORPHAN` の分類

参照 0 ＝ 異物とは限らない。ファイル冒頭を Read して 3 通りに分ける。

- **異物** — plan / spec / 調査メモ。移動先を提案する（plan → `docs/plans/`、spec → `docs/specs/`、判断記録 → ADR）
- **リンク漏れ** — 正当な詳細ファイルなのに親からリンクされていない。リンク追加を提案する
- **孤立した結論** — 結論が書かれているのに index に反映されていない。**最も危険**。index への反映を提案する

### 3. 「次に手を付けるなら」3 件

`-- ROWS --` から、効果 大 × 難易度 低〜中 × 制約 ✅ を出発点に 3 件選ぶ。
スコアを計算して並べるのではなく、**なぜ今これか**を各 1 行で書く。バンドルできる軽量項目は 1 枠にしてよい。

**「前提の変化」（依存先が既にリリースされた等）の検証はここではやらない。**
外部確認が要る項目は列挙に留め、`/feature-ideation discuss ID` を案内する。

## 出力テンプレート

```markdown
## Vault サマリ — <vault path> (<today>)

**最終更新** <date>（N 日前） / **最終棚卸** <last_sweep>

### ⏰ 要対応
（0 件なら「放置されている項目はありません」と明記する。セクションごと省略しない）

| 種別 | 対象 | 内容 | 経過 |
|---|---|---|---|

### 件数
- open N 件（カテゴリ別: ...）
- 状態別: ...
- 台帳: 実装済み N 件 / 不採用 N 件
- 詳細ファイル: N 件（うち異物 N 件）

### 🔀 index と実装・決定の食い違い
### 🗂 vault ディレクトリの衛生
### 🎯 次に手を付けるなら
### 次のアクション
```

アラートが 0 件のセクションも**省略せず「該当なし」と書く**。省略すると、確認したのか忘れたのかが
ユーザに区別できない。

## digest が届かなかったとき

digest ブロックが空か、明らかに壊れている場合のみ、上から順に試して**成功した時点で止める**。

1. `bash "${CLAUDE_PLUGIN_ROOT}/lib/vault-digest.sh"` を Bash ツールで実行する
2. それも失敗するなら、**先に**「bash が使えないため手集計になり、件数の精度が落ちます」と伝えてから
   Read と Glob で vault を読む。出力の冒頭に必ず警告を付ける
3. どの段階でも、**推測した数字を機械集計の結果であるかのように出さない**

## アンチパターン

- **digest を読み飛ばして vault を Read し直す** — 二度手間で、しかも数え間違える
- **digest の数字を「約 20 件」と丸める** — 実数のまま出す
- **アラート 0 件のセクションを黙って消す** — チェック漏れと区別がつかない
- **`XREF` を「status が古い」の一言で片付ける** — 何がどう違うかを書かないとユーザが結局両方読むことになり、
  このスキルの価値が消える
- **`frozen` を期限切れとして報告する** — 発火条件待ちには期限が無い。混ぜると狼少年になる
