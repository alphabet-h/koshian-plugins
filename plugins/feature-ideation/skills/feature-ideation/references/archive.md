# archive — 完了 / 却下になったアイデアを台帳へ移す

`/feature-ideation archive FI-012 completed` で起動する。
アーカイブ先は **vault 本体末尾の 2 表**（`## 実装済み台帳` / `## 不採用の記録`）。別ファイルは作らない。

## 手順

### 1. 対象を特定する

vault index から ID の行を探す。無ければ「ID `FI-012` は vault にありません」で**中止する**。

### 2. 行き先を確定する

| 引数 | 行き先 |
|---|---|
| `completed` / `done` / `実装済み` | 実装済み台帳 |
| `declined` / `却下` / `no` | 不採用の記録 |
| 自由文 | 内容から判断し、**どちらへ入れるかをユーザに確認する** |
| 省略 | `AskUserQuestion` で「実装済み / 不採用」を聞く |

重複・alias・上位項目への統合は**不採用の記録**で扱う（3 本目の表は作らない）。
理由欄に「統合: FI-021 と重複。出典情報は FI-021 の備考へ移設」のように書く。

### 3. 必須列を埋める（ここが要）

**実装済み台帳** `| ID | 名前 | 完了日 | 証跡 | 知見 |`

- **`証跡` は空欄禁止**。PR 番号 / タグ・version / commit / ADR のいずれかを最低 1 つ。
  複数あればスラッシュ区切り（`PR #72 / v0.12.0 / ADR-0004`）。
  分からなければ**ユーザに聞く**。推測で埋めない
- **`知見` は空欄禁止**。実装で分かったこと、特に**起票時の想定が外れた点**を 1 行で書くか、
  詳細ファイル・knowledge note へリンクする

> `知見` を必須にしているのは体裁のためではない。実運用で「GO 判定 → ADR → 実装完了」が 2 時間で走ったのに
> vault の index だけが起点で凍結し、同じディレクトリに置かれたトライアル記録へのリンクが
> vault からは 1 本も張られない、という事故が起きた。**リンクを張らないと台帳行が書けない**構造にすることで、
> 実装から vault へ戻る導線を強制する。

**不採用の記録** `| ID | 名前 | 判定日 | 理由 | 復活条件 |`

- `理由` は必須
- `復活条件` は「何が起きたら戻すか」。見込みがなければ `—` を明示（空欄＝未記入 と区別する）

新しい行は**先頭に追記**（日付の降順）。

### 4. index から行を削除する

`done` / `declined` は index に残さない。**取り消し線の墓標行を作らない**。
ID の欠番は台帳 2 表を引けば説明がつく。

同時に確認すること:

- `## 再評価キュー` にその ID の行があれば削除する
- `## 優先度ピック` にその ID が載っていれば、載ったまま完了した事実を記録するために**触らない**
  （`idea-check` の改訂トリガ T2 / T4 の判定材料になる）

### 5. 詳細ファイルは残す

物理削除しない。存在する場合は末尾に追記する。

```markdown
## 判定履歴

- **YYYY-MM-DD**: <completed / declined>。<理由の短縮>
```

frontmatter の `status` と `updated` も更新する。

### 6. 報告する

更新箇所を 2〜3 行で。台帳が 60 行を超えたら
「`<feature-ideas>/archive-<年>.md` への年次退避を検討してください」と添える。

---

## 条件トリガの隔離（vault に置いてはいけない持ち越し）

`archive` の判断中に「まだ却下ではないが、今は判断できない」項目が出てくる。これを vault に残すと腐る。

> **再評価の時期を自分の都合で決められる** → vault の `## 再評価キュー` に日付で書く
> **外部条件が満たされるまで判断できない** → vault の外へ出す

実運用では「2〜3 週間後に再評価」「Phase 1 の効果検証後に再評価」「次回監査時、または 6 ヶ月後」
「数日〜数週間後に reevaluate」の 4 種類が発生し、**日付に還元できたのは 1 つだけ**だった。
残りは日付比較では原理的に拾えないので、期限として書いた時点で誰にも気づかれずに放置される。

### 出す先の決め方

1. `known-issues.md` があればそこへ
2. 無ければ同等の器を探す（`TODO.md` の Deferred 節 / `BACKLOG.md` / GitHub Issues）。**あるものを使う**
3. どれも無ければ **vault と同階層**に `known-issues.md` を新設する。
   `<feature-ideas>/` の中には置かない（ファイル名規約に反する）。**新設は 1 度ユーザに確認する**

   ```markdown
   # 既知の残り課題

   発火条件が満たされるまで判断できない持ち越し事項。期限は持たない。

   ## <件名> (deferred, YYYY-MM-DD)

   - **状況**:
   - **判断保留の理由**:
   - **再評価 trigger**: <何が起きたら見直すか>
   ```

4. ユーザが新規ファイルを拒否したときのみ、vault に状態 `frozen` で残す。
   **再評価キューには載せない**（偽の期限を持たせない）。備考に `発火条件: ...` を定型で書く

`frozen` が 5 件を超えたら `idea-check` が切り出しを提案する。
